# Context: InvenTree Plugins

This context covers the shared conventions, structure, and workflow for any InvenTree-based plugin developed inside the toolkit. It is independent of any specific plugin domain.

## Scope

Applies to every plugin under `plugins/`. It covers:

- The standard plugin package layout (`<plugin_name>/`, `frontend/`, `pyproject.toml`, `README.md`).
- InvenTree plugin mixins (`SettingsMixin`, `UrlsMixin`, `UserInterfaceMixin`, `EventMixin`, `ScheduleMixin`).
- The devcontainer-based development environment and common commands.
- Documentation standards and file naming conventions.
- The test pyramid: unit tests, integration tests, and Playwright E2E tests.
- Build and deployment workflow.

It does **not** cover:
- The BOM/Build/Buy suite-specific domain model (see [`inventree-bom-build-buy-suite/CONTEXT.md`](../inventree-bom-build-buy-suite/CONTEXT.md)).
- The internal implementation details of any individual plugin (see `plugins/<name>/CONTEXT.md`).

## Key concepts

- **InvenTree Plugin:** A Python package that extends InvenTree using the `plugin` API and mixins.
- **Mixin:** A capability interface provided by InvenTree (e.g., `UrlsMixin` for API endpoints, `UserInterfaceMixin` for UI panels).
- **Plugin skeleton:** The minimal package generated by the `plugin-creator` tool (run as `create-inventree-plugin` or `python -m plugin_creator.cli` in the devcontainer).
- **Vertical slice:** One feature implemented end-to-end (user story → test → implementation → API → UI → docs).
- **Devcontainer:** The Docker-based environment that hosts InvenTree and the plugins for development.
- **Deterministic test chain:** The sequence of unit, integration, and E2E tests run before considering a feature done.
